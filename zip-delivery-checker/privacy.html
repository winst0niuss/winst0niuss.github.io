ZIP Delivery Checker privacy policy

Last updated: November 5, 2026

ZIP Delivery Checker ("the app", "we") is an app for Wix stores that lets shoppers check on a product page whether the store delivers to their ZIP code or postcode. This policy explains what data the app uses and why. By using the app, you agree to this policy.

Data from shoppers

  • When a shopper checks a code, the shopper's browser sends only that code to the app on the store's site. The app answers with the delivery time, estimated cost and note of the matching delivery area, or that the store does not deliver there.
  • If the code is outside the store's delivery areas, the app adds it to the store's Requested, not covered list. The list keeps only the code, how many times it was checked and the date of the last check. It does not keep the shopper's name, email, IP address, the time of day or any other link to the shopper.
  • To show the answer on the next product page, the shopper's browser remembers the last code in its own local storage (under the name zdc-code). This stays in the shopper's browser and is not sent anywhere except when the code is checked again. The shopper can clear it by clearing the site data in the browser.
  • At checkout, Wix sends the app the checkout details so it can check the delivery address (Wix Validations permission). If the store owner has turned the checkout check on, the app reads only the country and postal code of the shipping address, the chosen delivery option and whether the order has items that need shipping, to decide whether to show a warning or stop the order. It does not store anything from the checkout and does not use the shopper's name, street address, email or payment details.
  • The app does not use cookies, tracking or analytics.

Data from store owners

  • The app stores, in data collections on the site's own Wix account and not on servers of ours: the delivery areas (area names, codes, delivery time, estimated cost, free delivery threshold and note), the checkout check settings (mode, country and message) and the Requested, not covered list. Only the app's server can read these; shoppers get only the answer for the code they check.
  • The look settings of the check (texts, accent color) and whether the plan is active are stored in a separate data collection that anyone can read, because the product pages need them.
  • The Add regions and Add by distance tools work in the store owner's browser, on postal code data built into the app: U.S. Census Bureau data for the United States and GeoNames data (geonames.org, CC BY 4.0, modified) for Austria, Belgium, France, Germany, Italy, the Netherlands, Poland, Spain and the United Kingdom. The postal code the owner enters for a distance search is not sent or stored. A file imported with Import from file is read in the browser; only the codes found in it are added to the area.
  • The app reads the app plan from Wix to know whether to show the check. It does not store the plan details.
  • If you ask Aria about delivery, the app returns the delivery areas, the plan state, the checkout check settings and the most requested uncovered codes of the current site to Aria inside Wix. Aria can only read, not change anything.

The app does not send emails or notifications. We do not sell data and we do not use it for advertising.

Where data is processed

The app runs on Wix hosting, and data stays in the site's Wix account. Wix acts as our service provider. If you email us, we use your message and address only to answer you.

Retention, access and deletion

Delivery areas and settings stay on the site until the store owner changes or deletes them in the app dashboard. The Requested, not covered list keeps up to 300 codes; when it is full, the least requested code makes room for a new one, and the owner can clear the list at any time in the dashboard. Removing the app takes the check off the site and stops the checkout check; Wix may keep or delete the app's data collections under its own rules. To ask a question about your data, email us.
